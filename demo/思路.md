  2. 改动点 A：把“效率权重”真正用起来

  你现在：

  _CANDIDATE_INCOME_WEIGHT = 0.8
  _CANDIDATE_EFFICIENCY_WEIGHT = 0.2

  在 agent/_helpers.py:85-86。

  很多队伍初赛收益高是因为重收入，但到复赛/决赛，高运价长途单会把车甩到荒漠，下一单找不到，反而总收入更低。

  建议做一组对照实验：

  ┌──────────┬───────────────┬───────────────────┬────────────────────────────────┐
  │   方案   │ income_weight │ efficiency_weight │            预期效果            │
  ├──────────┼───────────────┼───────────────────┼────────────────────────────────┤
  │ 当前     │ 0.8           │ 0.2               │ 单单收入高，但可能被长途陷阱坑 │
  ├──────────┼───────────────┼───────────────────┼────────────────────────────────┤
  │ 效率优先 │ 0.4           │ 0.6               │ 更爱短平快、留在热点区         │
  ├──────────┼───────────────┼───────────────────┼────────────────────────────────┤
  │ 纯效率   │ 0.2           │ 0.8               │ 激进周转，适合货源密集场景     │
  └──────────┴───────────────┴───────────────────┴────────────────────────────────┘

  跑 3 组看哪个 net_income 高。通常货源越密集，efficiency 权重应该越高。

  3. 改动点 B：把目的地加分改成“两步 rollout”

  你现在 _apply_destination_market_value 是给 score 加一个 bonus，但它和 immediate income 是线性相加的，很容易被一単高价压倒。

  改成这样：对每个 top-10 候选，算

  total_value(candidate) = income(candidate)
                         + gamma^(total_time_hours) * V(destination)
                         - V(current) * total_time_hours / 24

  其中 V(destination) 用你的 MarketMemory.query(end_lat, end_lng, finish_minutes)。

  更直接一点：在 model_decision_service.py 的选单处（best = max(filtered_candidates, key=...) 之前），新增一个 _apply_two_step_rollout_score：

  def _apply_two_step_rollout_score(self, driver_id, candidates, progress_minutes, status):
      market_mem = self._market_memories.get(driver_id)
      if not market_mem:
          return candidates
      for c in candidates:
          end = c.get("end") or {}
          finish_min = progress_minutes + int(c.get("total_time", 0))
          v_dest = market_mem.query(end["lat"], end["lng"], finish_min, metric="top30_avg")
          if v_dest:
              hours = c["total_time"] / 60.0
              future = (0.85 ** hours) * v_dest * (hours / 2)  # 下一单的期望收益
              c["score"] = round(c["score"] + future, 2)
              c["rollout_bonus"] = round(future, 2)
      return candidates

  然后在主流程里，在 _apply_destination_market_value 之后调用它。

  这个改动的核心思想就是你说的“概率性匹配”：不接这単只看价，而是看“接完这一车之后，下一车大概能赚多少”。

  4. 改动点 C：修 MarketMemory 的偏差

  你 agent/market_memory.py:120-122 里扩散用的是：

  gross_net = price - haul_cost

  但人真正赚的是 price - (pickup_deadhead + haul) * cost_per_km。如果你的 pickup 空驶很远，这个扩散值会虚高，导致 Agent 误判某区域很热。

  可以改成：

  pickup_km = ...  # 从 query item 的 distance_km
  true_net = price - (haul_km + pickup_km) * cost_per_km

  或者至少把 cost_per_km 用进去，而不是只扣 haul_cost。
